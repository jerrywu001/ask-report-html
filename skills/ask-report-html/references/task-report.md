# 任务收尾结果报告

此文件只用于有实际改动的执行任务。遵守 SKILL.md 的触发门槛；普通提问、只读调查、计划和技能设置回合不生成报告。

## 1. 先确定本轮改动归属和文件数

非主动调用时，先读取本 skill 的 `auto-report.json` 中 `minChangedFiles`（默认 5，缺失或非法时也用 5）。仅在符合下面口径的不同文件数 **大于等于阈值**、且任务准备最终交付时生成报告。少于阈值直接文字交付；用户主动要求本 skill 或 HTML 时不受数量限制。

- 实际新增、修改、删除的源码、业务文档、配置文件均可计数。
- 同一文件只算 1 个；不按字段、改动行数、调用次数或提交次数计数。
- 归属不明确、改动已完全撤销或只有过程产物的文件不计入。
- 不拆文件、不添加无意义修改来凑门槛。

- 从本任务的操作记录、入场基线和验证结果中提取改动。
- 只报告本任务修改的文件、配置和行为；排除用户既有改动和并发会话改动。
- 不能把整个工作区 diff 当作自己的成果。无法确定归属时，明确写“归属未确认”。
- 仅生成规划、日志、缓存、截图、报告或纯生成产物，不算实质改动。
- 项目禁止 Git 时，不为写报告执行 Git；使用已有操作记录或文件对照。
- 报告生成不授权暂存、提交、推送、部署、业务写操作或新增 hooks。

## 2. 报告内容：2–5 个面板

按真实内容选择，不为凑数量添加面板。小改动可用“结果 / 改动与验证”两个面板。

| 面板 | 必答问题 | 内容 |
|---|---|---|
| 结果 | 本轮交付了什么？ | 目标、已完成 / 部分完成 / 阻塞、用户可见效果 |
| 改动 | 哪些地方变了？ | 本任务路径、关键行为变化、必要的前后差异 |
| 验证 | 有哪些可靠证据？ | 实际命令或检查、通过 / 失败 / 未运行、证据路径 |
| 边界 | 哪些仍未解决？ | 已知问题、未验收项、未操作项 |
| 下一步 | 用户还需做什么？ | 只写必要动作；没有就省略 |

- 使用用户的语言。结论放在最前。
- 没有运行测试时写“未运行”，并简述原因；不能据此写“全部通过”。
- 检查失败时写“失败”，区分本轮问题和有证据支持的既有问题。
- 等待用户确认时只发确认问题，不为了收尾强行生成报告。
- 有改动但任务只能部分交付时，生成部分结果报告，不伪称完成。
- 只引用已有证据，不为填报告重跑高成本或高风险检查。
- 不收集或嵌入密码、token、认证文件、原始会话或未脱敏业务数据。
- 文件列表和简短差异通常已足够；不要默认把全部私有源码嵌入页面。

## 3. 输出位置与去重

- 报告统一保存为 `~/.ask-report-html/<task_xxx>/<报告名>.html`，默认文件名为 `report.html`。
- 任务目录使用 `task_<项目名>-<任务名>` 等可识别名称；继续同一任务时复用原目录。
- 草稿如需落盘，保存为同目录的同名 `.md` 文件。
- 实际 `-o` 参数使用 `$HOME/.ask-report-html/...` 或展开后的绝对路径，不把 `~` 放在引号内当作已展开路径。
- 不再将 HTML 报告及其草稿放在项目 `.agent-work/`、`~/.agent-work/`、`doc/` 或 `docs/`，也不暂存或提交。
- 其他临时编码材料按所在项目的既有规则保存；本 skill 只规定 HTML 报告及其草稿的目录，不要求接收者采用作者的项目配置。
- 一个任务只维护一份报告。修正结果或继续同任务时，更新这份报告。
- 多个会话处理同名任务时，用已有会话标识区分目录，避免覆盖别人的报告。
- 报告及其草稿不计入下一轮的实质改动，避免“报告触发报告”。

## 4. 渲染

先把示例中的项目名、任务名和报告名替换为本任务的真实名称。不要原样使用占位符。若要引用项目源码，仍从项目目录执行 CLI，只通过 `-o` 指定报告位置。

````bash
node "$HOME/.agents/skills/ask-report-html/scripts/render.mjs" render - --no-open -o "$HOME/.ask-report-html/task_project-task/report.html" <<'AM_EOF'
---
title: 任务结果报告
lang: zh
---
## A 结果
写入本轮真实结论和交付状态。

## B 改动与验证
| 项目 | 结果 | 证据 |
|---|---|---|
| 本轮改动 | 写入实际行为变化 | 写入本任务文件路径 |
| 实际检查 | 写入通过、失败或未运行 | 写入命令或日志路径 |
AM_EOF
````

此示例展示格式，不包含实际任务数据。按内容选择表格、callout、tree 或 diff；不要强行加流程图。

- 默认使用 `--no-open`，不自动打开浏览器，也不启动 `am serve`。
- 同一报告再次渲染时，保持相同 `-o` 路径，直接覆盖更新。不要加 `--replace`：当前 CLI 只允许它指向默认 pages 目录，不接受任务目录。
- 只改一个面板时，使用 `am patch <报告路径> --panel <标题> --no-open`。
- 成功后确认 HTML 文件存在且非空。页面渲染成功不等于业务验证通过。
- 渲染失败时修正格式；重试仍失败就返回文字结果并说明报告未生成。
- 最终回复保留简短结论、重要失败或边界，以及报告链接。

## 5. 可选 hooks 的边界

默认依靠全局收尾指令调用本 skill，不安装 hooks。

若用户另外要求可靠的漏报检查，可为各工具分别适配生命周期：

- Pi：用 extension 的 `agent_before_settle` 检查；`agent_settled` 只做完成通知。
- Claude Code：在 `Stop` 检查，并用 `stop_hook_active` 防止反复续行。
- Codex：支持 hooks 的版本可在 `Stop` 检查；旧版本需核对能力。`notify` 不是等价的阻塞校验。

检查必须同时判断任务归属、有效改动文件数是否达到配置阈值、当前交付状态、报告是否有效和本次是否已提醒。不要仅凭停止事件、工作区有 diff、文件修改时间或最终回复有“完成”就认定需要报告。不要将子代理结束当作整个任务结束。

缺报告时最多请求一次补报，随后放行并记录异常；不要死循环或强制追加任务。保留已有 hooks 与权限策略。若接入事件脚本，先核对本机版本和官方事件契约，再取得用户对安装范围的确认。
